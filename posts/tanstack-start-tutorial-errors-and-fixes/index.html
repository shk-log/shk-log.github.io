TanStack Start 무작정 따라하기 : 삽질하면서 배운 풀스택의 맛

February 10, 2026 · 2 min · JSON

TanStack Query를 처음 접했을 때도 느꼈지만, 역시 백 번 보는 것보다 한 번 직접 만들어보는 게 이해가 훨씬 빠르다. 이번에는 TanStack Start의 원리를 밑바닥부터 파악해보고자 ‘Build from Scratch’ 문서를 보며 코드를 한 줄씩 직접 타이핑했다.

https://tanstack.com/start/latest/docs/framework/react/build-from-scratch

복붙을 하지 않았어니 이런 에러를 마주할수 있었다.

첫번째 Tanstact start error : HTTP 500#

Tanstack start는 프론트와 백엔드 모두를 책임지는 풀스택 프레임워크이다. 그래서 처음 예시를 보면서도 이게 프론트의 역할일까? 백엔드의 역할일까? 만약 예시가 아니라 프로젝트가 커지면 어떻게 분리해서 결합도를 낮추고 응집도를 높일까라는 생각을 하면서 봤다.

500 에러를 만났을 때 서버 로직의 문제임을 직감했고, 원인은 의외로 단순했다. getRouter 함수에서 router 인스턴스를 반환(return)하지 않았던 것. 자동 생성된 routeTree.gen.ts가 이 인스턴스를 참조하다 보니 발생한 문제였다.

return router를 입력하니 500에러는 사라졌지만 다른 에러가 나타났다.

두번째 Tanstact start error : NaN (Not a Number)#

이 예제는 클릭할때마다 숫자가 올라가는 예제이다. 최초에는 count.txt파일 여부를 확인하고 없으면 파일을 생성하면서 숫자 0이 생기고, 클릭할때마다 숫자가 올라가는 코드다.

자가 올라가야 할 자리에 NaN이 떴다. 확인해 보니 count.txt에 숫자가 아닌 ${count+data}라는 문자열이 그대로 적혀 있었다. 백틱을 써야 할 자리에 일반 따옴표(’)를 쓰는 바람에 연산이 아닌 문자열로 저장된 것이다. 타입스크립트가 모든 걸 잡아줄 거라 믿었지만, 이런 런타임의 사소한 오타까지는 완벽히 막을 수 없다는 교훈을 얻었다.

타입 선언한 적이 없는데 타입이 존재한다 | 자동 타입 추론#

코드가 제대로 작동되는 것을 보다가 예제코드에서 count 나 state변수에 타입선언하는 코드가 없다는걸 발견했다.

![[Pasted image 20260120114229.png]]

따로 타입을 선언한 적이 없는데도 count 변수는 이미 number 타입이었다. readCount 함수의 parseInt 리턴값을 보고 타입스크립트가 타입을 자동으로 추론해준 것이다. 명시적인 선언 없이도 데이터의 흐름에 따라 타입이 결정되는 방식이 무척 매력적이었다.

async function readCount() {
	return parseInt(
	await fs.promises.readFile(filePath, 'utf-8').catch(()=>'0'),
	)
}

더 편리해진 SPA#

이전 프로젝트에서는 TanStack Query를 쓰며 queryKey를 관리하고 상태 변화에 따라 API를 호출하는 방식에 감탄했었다. 하지만 TanStack Start는 한 단계 더 진화했다.

리액트에서 TanStack Query를 이용해 SPA를 구현할 때는 보통 queryKey가 참조하는 변수를 추적하고, 그 내용에 변화가 감지되면 API를 다시 호출해 화면을 그려주는 방식을 사용한다. 즉, **‘상태가 바뀌면 데이터를 가져와라’**라는 간접적인 흐름이다.

function Home() {
	const router = useRouter()
	const state = Route.useLoaderData()

	return (
		<button
			type='button'
			onClick={() => {
				updateCount({data:1}).then(() => {
				router.invalidate()
				})
			}}
        >
			Add 1 to {state}?
		</button>
	)
}

리액트에서 TanStack Query 이용해서 spa 하려면 TanStack Querykey로 변하는 변수를 추적하고 변수 내용에 변화가 감지되면 다시 api 호출해서 그려주는 방식인데 반해 . updateCount 함수로 작성한 다음(.then) router.invalidate() 를 이용해서 바뀐데이터를 바로 가져올 수 있다. 이 명령어가 없으면 새로고침 해야 입력된 내용이 반영되어 바뀌는데, 이 문장 하나로 자연스럽게 갱신해준다.

예제 하나의 코드만 살펴봤는데 왜 tanstack start가 왜 차세대 프레임워크라고 하는지 깨닫는 순간이었다.
